# Scene Builder

## Workflow

Create or duplicate a scene, set its name/summary/tags/favorite state and concurrency, then add activation and deactivation actions. Stable IDs are generated by the app; dependencies reference those IDs. Reordering changes presentation and deterministic scheduling priority, not dependency meaning.

Each action includes common configuration: label, dependencies, failure policy, retry policy, idempotency policy, timeout, optional condition, health checks, and output retention. Action-specific fields are typed; process arguments are separate entries, never a shell command.

## Validation

Save is blocked for duplicate IDs, missing dependencies, cycles, invalid parallelism/timeouts/retries, unsupported schemes, relative/restricted executables, unsafe arguments/control characters, invalid paths/ports, destructive Docker combinations, invalid frames, or incomplete integration data. Validation errors include the field path.

## Readiness design

Add dependencies when order matters. Add a health check when successful start is not sufficient proof of readiness. Mark nonessential actions with an explicit non-blocking failure policy. Put cleanup in deactivation actions and choose ownership-aware stop behavior. Avoid fixed waits when a bounded health check can observe the real condition.

## Portable and secret data

Prefer bookmark references for user-selected files that must survive sandbox/security-scoped access changes. Use `secretReference` environment values backed by Keychain. Never place passwords, tokens, private keys, or sensitive query values directly in labels, arguments, URLs, or plain environment fields.
